# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

## Selected product direction

- The desktop organizer is a persistent, compact icon container placed directly on the Windows desktop; it is not a folder that opens into a separate panel.
- Shortcut icons remain visible and launch with a single click.
- The container can be dragged and freely resized, with the icon grid reflowing to fit.
- The selected visual target is the dark smoke-glass 4-by-3 icon block from the revised third concept.
- Do not show an external title, outer selection frame, external resize arrow, header, toolbar, popup, or expanded state. The only resize affordance is a subtle control inside the container's bottom-right corner on hover.
- Keep the native organizer elegant, lightweight, and folder-like. Use a restrained neutral smoke-glass surface rather than a decorative floating card.
- Do not use blue glow, blue focus halos, or conspicuous blue animation. Hover and press feedback should be short, neutral, and subtle, with no continuous animation.
- Use the Windows DWM anti-aliased outer corner rather than a manual GDI window region; avoid bubbly rounding and jagged pixel-clipped edges.
- Do not draw a white or translucent-white outline around the organizer surface, including on hover.
- Organizer blocks are desktop-layer widgets: they must not activate or steal focus during normal icon, drag, resize, hover, tray-show, or visibility interactions, must remain behind ordinary application windows, and must remain visible when Windows “Show desktop” (`Win+D`) is active.
- Treat Windows 11 24H2's `Progman`-hosted `SHELLDLL_DefView` hierarchy and pre-24H2 `WorkerW` hierarchy separately. Detect the actual Show Desktop state with a hidden bottom probe and temporarily anchor organizers just above the desktop-icons host, then return them to the ordinary desktop-bottom band when open windows are restored. Do not reparent WPF windows across Explorer processes because `SetParent` can reset DPI awareness.
- Show Desktop transitions must not visibly blink. React to Explorer's desktop-container `EVENT_OBJECT_REORDER` in the same compositor frame, use a short 2–10 ms foreground-event retry only as a race fallback, and retain the low-frequency state timer solely as recovery maintenance.
- Provide an explicit keyboard-only interaction mode through the tray and `Ctrl+Alt+D`. It may temporarily activate the most recently used visible organizer, places focus on its first shortcut, and exits with `Escape`; leaving the mode restores the previous foreground window and the normal non-activating desktop layer.
- Use a restrained neutral frosted-glass background. Global in-app appearance settings expose independent 0–100% background transparency, fixed lightweight glass on/off, black/white background tone, and magnetic snapping on/off; do not expose a fake blur-strength control, and preserve sharp full-opacity app icons.
- Black background tone uses light internal labels and controls; white background tone uses dark ones. Temporary menus, tooltips, toasts, and custom dialogs may remain neutral dark chrome.
- At effectively transparent backgrounds (92% transparency or greater), sample the wallpaper beneath each organizer and switch its optional name/control foreground between neutral light and neutral dark for legibility; do not add a text tile, halo, or shadow.
- Frosted glass is only accepted when the softened wallpaper visibly varies through the organizer surface; a uniform black or flat gray fill is a failed fallback, even if the native backdrop call reports success.
- Appearance and magnetic-snap settings are one synchronized global state for every organizer block. Present them in one App-level, ownerless custom settings window rather than inside a block; changes preview on all existing and newly created blocks in the same render frame.
- Percentage settings must be directly editable as well as draggable: provide a neutral slider, numeric percentage input, and small step controls. Cancel/Escape/close restores the committed global appearance; save commits it transactionally.
- Folder-name and shortcut-icon-name toggles belong in the settings window's “current organizer block” section, not in the organizer context menu. These two preferences remain independently persisted per block; cancel, Escape, or closing settings must roll back their pending preview together with any pending global changes.
- The independent settings window also contains a “hidden organizer blocks” management section that updates from the current running session. List every currently hidden block separately and allow each one to be restored immediately on its own; restoring preserves its position, size, shortcuts, name, and display preferences. Visibility is runtime-only: do not persist hidden state across launches or include restore actions in the appearance/current-block Save/Cancel transaction. Even when every block is hidden, the tray must still open settings for individual recovery, and double-clicking the tray icon must restore all blocks.
- Magnetic snapping preserves the existing release-time edge/alignment and 10 px gap position snap. Moving a block must never change its width or height, and the snapped position is persisted.
- The empty organizer must remain visually blank. Do not show onboarding icons, instructional copy, or “drag shortcuts here” placeholder text inside it.
- Treat the Windows user and public Desktop directories as the source of truth for ordinary desktop items. Organizer blocks are mirrored classification views, not backing storage folders: assigning, reordering, or moving an item between blocks must update only persisted identity/category/order metadata and must not copy or relocate the real desktop file. Launch, rename, delete, and external filesystem changes operate on and synchronize with the real desktop item. Folder mapping is a separate explicit view over an existing directory and must not create a folder shortcut.
- Keep Explorer's desktop presenter active so unassigned native icon positions, native selection, wallpaper drag-marquee, desktop context menus, and ordinary Shell interactions coexist with organizer blocks. Classification is explicit: newly discovered Desktop items stay unassigned and native until the user adds them to a block. Selectively suppress only assigned filesystem items from the native Desktop using reversible visibility state without relocating them; moving an item “to Desktop” removes its organizer assignment and restores native visibility. Observe the native wallpaper marquee without consuming input and update intersecting organizer icons continuously while the pointer moves, including immediate deselection when the rectangle shrinks or leaves an icon. Support Ctrl-additive selection and clear on an unmodified wallpaper click. Organizer marquee selection is runtime-only and must never be persisted.
- Desktop classification supports direct bidirectional drag and drop. Dragging a native Desktop item into a block classifies it without copying or moving the real file; dragging a block item onto Explorer's desktop unassigns it and restores native visibility. A block-to-block drop remains an internal classification move, while Escape or a drop over any non-desktop application cancels without changing classification. Keep the drag cursor neutral and do not send a same-folder file move to Explorer.
- Bidirectional drag feedback must feel immediate: update the organizer collection in the release frame, then perform reversible Explorer visibility synchronization at background dispatcher priority and request non-blocking Shell delivery. Accept both filesystem `FileDrop` and Shell `CFSTR_SHELLIDLIST`/CIDA payloads so virtual desktop items such as Recycle Bin can move into and out of a block. Preserve and restore the user's prior registry visibility value for managed virtual icons.
- During native-to-organizer drag enter, hover, and drop, negotiate an effect that is actually present in the Shell source's `AllowedEffects`. Prefer Link for virtual namespace items and Copy for filesystem items, with Move/other supported effects as fallbacks, so Explorer never shows a false prohibited cursor over a valid organizer target.
- Support multiple independent organizer blocks. Persist each block's stable identity, shortcuts, position, size, name, and name-visibility setting across launches.
- Folder names are optional and, when enabled, appear only as a quiet single line inside the block. Hiding the name returns the full area to the icon grid.
- Shortcut icon names are independently optional per organizer block. When enabled, show a quiet single-line ellipsized label directly below each icon with no tile, shadow, or outline; temporarily suppress labels in layouts too dense to keep icons legible while preserving the user's preference.
- Each organizer block has a persisted icons-only option in the settings window's current-organizer section. It hides that block's folder surface, backdrop, hover edge response, resize marks, folder name, and shortcut labels while preserving the saved name preferences for restoration. Icons remain sharp and the transparent move, context-menu, scroll, and resize hit areas remain usable.
- Icons-only mode must keep DWM composition enabled and, on Windows 11 24H2+, enable redirected-bitmap alpha so the transparent client stays genuinely transparent without a white fallback. It suppresses the system border and rounded clip while the normal surface restores DWM-owned anti-aliased rounding; do not disable the whole DWM non-client rendering policy because that can produce an opaque white client area.
- Icon layout is independently persisted per organizer block and offers exactly four fixed modes: Large, Medium, Small, and List. Resizing a block only reflows the fixed-size items into a different row/column count; it must never scale icons continuously with the window. List mode uses one column and always shows shortcut names, while preserving the block's previous icon-name preference for grid modes.
- Shortcut rows default to left alignment from the layout's fixed internal padding; do not horizontally center the icon group when unused width remains on the right.
- When fixed-size shortcut content exceeds the organizer height, keep it inside the block and support restrained, smooth vertical wheel/touchpad scrolling without adding a permanently visible scrollbar or decorative scroll chrome.
- Moving an organizer may use the existing optional edge/gap position snap, but it must never automatically change that block's width or height.
- Bottom-right resizing remains completely free while the pointer is held. On release, choose the closest spatially aligned organizer above, left, or right; if width and/or height is sufficiently close, independently animate each close dimension to match that neighbor. A dimension outside the threshold remains exactly as released; add no alignment text, extra marks, glow, pulse, live detent, or other visual feedback.
- Release-time width and height matching are independently validated against the current work area and minimum dimensions. Permit a small pointer overshoot into a left/right neighbor, and cancel any prior release animation immediately when a new move or resize begins.
- Organizer blocks may be flattened to a 120 DIP minimum height, enough for one full-size icon row with optional labels when width permits. Keep a small visual gap between each icon and its label.
- The organizer minimum width follows its committed fixed layout and must preserve one complete icon cell: 114 DIP for Large, 94 DIP for Medium, and 76 DIP for Small or List. Layout previews may remain non-destructive; committing a larger mode expands a narrower block to its new one-icon minimum. Retain the 120 DIP minimum height.
- The bottom-right resize affordance keeps a transparent hit target but draws only two quiet diagonal marks; do not place a rounded plate, border, outline, or other surrounding contour behind it.
- Shortcut focus must never draw a box, rounded rectangle, tile, or double outline around the icon. Mouse clicks leave no persistent focus decoration; keyboard-only focus uses a short, quiet neutral underline that adapts to the current foreground tone.
- Shell icon extraction must not expose faint square canvas frames. Remove only the complete low-alpha perimeter signature produced by affected Shell bitmaps; preserve legitimate opaque icon edges, transparent padding, soft shadows, and the original high-resolution artwork.
- When that exact abnormal Shell canvas signature also leaves the artwork undersized, trim its excessive transparent canvas and normalize the artwork to roughly 82% of a square icon canvas. Apply this only to already-detected abnormal framed bitmaps so intentionally small or padded normal icons remain unchanged.
- Hover and press motion stays short, neutral, non-looping, and respects reduced-motion settings: use only a very small icon lift/scale and restrained smoke-surface response.
- Confirmations, warnings, move/copy choices, and rename prompts use an independent App-level, ownerless custom smoke-gray dialog window so they are never clipped or constrained by an organizer block. Settings and these ownerless dialogs appear in the taskbar while open so they can be recovered after switching apps; settings keeps its footer visible and scrolls the body on short/high-DPI work areas. Do not use an in-block overlay or native `MessageBox`; the system file picker may remain native.
- Keep the shared Shell icon cache bounded so repeated shortcut churn cannot grow memory without limit.
- Resource optimizations must preserve the current visuals and interactions. Keep tray and monitor-work-area integration on native Win32 so the WPF process does not load Windows Forms/System.Drawing UI stacks; instantiate only the active grid/list shortcut template; keep the Shell bitmap cache as a 96-entry LRU and prune obsolete entries when shortcuts or organizers are removed.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.
