# Yit Desktop Fold 完整审查

审查日期：2026-08-02

## 范围

审查当前发布版的桌面整理块、右键菜单、设置窗口、自绘对话框、桌面层级、吸附与缩放、状态持久化、快捷方式安全、键盘可访问性和运行资源占用。本轮仅审查，没有修改产品代码或用户状态。

## 总体结论

核心体验已可用，视觉风格、图标呈现、设置事务和快捷方式恢复机制都比较稳定。发布构建以警告视为错误仍为 0 错误、0 警告，现有自动化检查全部通过。但仍有 2 个高优先级问题和若干中低优先级边界缺陷；其中 `Win+D` 会让桌面整理块消失，是目前最明显的核心行为问题。

## 问题清单

### P1 — `Win+D` 会隐藏所有整理块

证据：步骤 5。`DesktopZOrderHost.UpdateForForeground` 只调用 `SetWindowPos(..., HWND_BOTTOM, ...)`，而 `DWMWA_EXCLUDED_FROM_PEEK` 不负责抵抗“显示桌面”。这破坏了桌面挂件最核心的可见性预期。

### P1 — 整理块的键盘路径实际上不可进入

整理块常态一直带 `WS_EX_NOACTIVATE`，代码中没有任何地方调用已有的 `SetInteractionActivation(true)`，也没有可从托盘进入的键盘模式。虽然快捷方式和缩放控件定义了焦点/方向键行为，但纯键盘用户无法把焦点送入整理块，因此单击启动、Tab 焦点、Alt+方向移动等键盘实现基本不可达。

### P2 — 高度吸附会被目标块的宽度提前过滤

`ResizeThumb_DragCompleted` 在调用独立宽高吸附前，先排除了宽度小于当前 `MinWidth` 或大于当前可用宽度的邻居。即使该邻居的高度完全合法且接近，也不会触发高度匹配，与“宽高独立判断”不一致。

### P2 — 快速开始第二次拖拽时，上一段释放动画可能继续写尺寸

`AnimateWindowBoundsAsync` 使用独立 `DispatcherTimer`，没有取消令牌或版本号。用户松手触发 115ms 吸附动画后立刻再次拖动，上一计时器仍可能继续设置 `Width/Height`，造成短暂回跳、闪动或错误落点。

### P2 — 右侧邻居的吸附在轻微越界后失效

右侧候选要求 `target.Left >= resizingBounds.Right`。拖动右下角时一旦右边缘越过右侧块左边缘哪怕约 1 DIP，该块就不再是候选；这使右侧吸附比左侧吸附更脆弱，并浪费了一部分 10 DIP 尺寸阈值。

### P2 — 设置窗口在高缩放/矮屏幕上可能被裁切

设置窗口固定为 `390 × 610 DIP`、不可缩放，主体没有整体滚动。定位代码只夹取左上角，不会缩小窗口或提供滚动；当工作区高度小于约 `654 DIP` 时，底部“取消/保存”会超出屏幕。

### P2 — 全局对话框切到后台后缺少可靠的找回入口

自绘对话框 `ShowInTaskbar=False`，WPF 为其建立隐藏 owner；来源整理块在等待期间被禁用。用户若点到其他应用，对话框可能被覆盖且不在任务栏中，整理块又不能重新打开它。设置窗口可通过托盘再次前置，但重命名、删除等一次性对话框没有同等入口。

### P3 — 100% 透明时，文字对比度完全依赖壁纸

白色底色固定使用深色标签，黑色底色固定使用浅色标签。背景透明度为 100% 时已经没有稳定底色；若开启文件夹名或图标名，文字可能落在同色壁纸区域而不可读。截图只能确认风险，不能证明所有壁纸下的对比度。

### P3 — 状态保存对注册表读取异常的保护不完整

`TrySaveAll` 在 `try` 块外调用 `StartupService.IsEnabled()`；受策略限制时产生的注册表异常可能绕过现有保存错误提示并进入未处理异常路径。`StateStore.TryLoad` 同样未捕获读取权限异常，可能导致启动失败。

### 性能观察 — 尚不能判定为泄漏

当前 3 个整理块、13 个快捷方式，在完成设置与对话框审查后采样为约 `223.3 MB` 工作集、`132.9 MB` 私有内存、1658 个句柄。对 WPF 应用不算异常崩溃级别，但高于“极轻量”的目标。Shell 图标缓存没有容量上限，长期增删大量不同快捷方式会让缓存只增不减。需要冷启动基线和 30–60 分钟重复操作采样后，才能判断是否存在真实泄漏。

## 已确认的优点

- Release 构建在 `TreatWarningsAsErrors` 等价检查下为 0 错误、0 警告。
- 快捷方式导入/恢复、多块状态、设置事务、四种固定布局、滚动和吸附几何自动化检查全部通过。
- `state.json` 和备份均存在，审查过程中没有改变用户状态。
- 图标清晰，无方框、白边或持久焦点框；整理块圆角与玻璃背景在当前屏幕上稳定。
- 普通右键交互没有改变前台窗口句柄。

## 证据限制

- 未逐个启动 13 个真实快捷方式，避免产生外部副作用。
- 未覆盖混合 DPI 多显示器、Explorer 重启、睡眠唤醒和任务栏自动隐藏。
- 截图不能证明完整 WCAG 合规，也不能量化 115ms 动画的逐帧稳定性。
- 本轮没有进行长时间内存/句柄泄漏压测。

## 推荐修复顺序

1. 先修复 `Win+D` 桌面层行为。
2. 增加可进入/退出的键盘操作模式。
3. 修复尺寸吸附的独立轴过滤、动画取消和右侧轻微越界容差。
4. 让设置窗口支持矮屏幕滚动，并为全局对话框提供可靠的前置/找回机制。
5. 最后处理透明文字对比度和长期资源采样。
