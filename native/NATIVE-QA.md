# Native QA

## Final build

- Target: .NET 8 WPF, `win-x64`, framework-dependent, five-file lightweight distribution.
- Build: succeeded with 0 warnings and 0 errors.
- Automated checks: shortcut copy/removal safety, independent per-folder icon-name, icons-only, and icon-layout state, black/white global appearance round-trip, 0/100% opacity boundaries, isolated combined global/current-organizer drafts, runtime hidden-list updates, exact hidden-block restoration without placement/content loss, restore independence from settings Save/Cancel, invalid-value normalization, old-state/schema-v1 migration, corrupt-state recovery, fixed Large/Medium/Small/List geometry and resize-only reflow, complete vertical scroll extents, list-name visibility and icons-only label suppression, position-only edge/gap snapping, independent above/left/right-neighbor width/height release snapping, and small right-neighbor resize overshoot tolerance all passed.
- Direct launch: a UI Automation invocation of the Notepad shortcut created exactly one Notepad process.
- Shell icon cleanup: real 128 px Bambu Studio and ChatGPT Shell bitmaps had their identical three-pixel low-alpha canvas frames removed; real Figma and LM Studio bitmaps did not match the perimeter signature and remained byte-format-equivalent through the normal extraction path.
- Shell icon sizing: excessive padding was cropped only after the abnormal perimeter signature matched, retaining approximately 9% breathing room on each side. A packaged desktop inspection confirmed ChatGPT and Bambu Studio now match neighboring icon weight without reintroducing the frame or resizing unaffected icons.
- Single instance: a second launch exited and reused the existing organizer process.
- Desktop behavior: organizer windows form a non-activating layer immediately above Explorer's desktop and below ordinary application windows. A hidden bottom probe detects the actual Show Desktop Z-order state every 250 ms. On Windows 11 24H2 it recognizes `SHELLDLL_DefView` under `Progman`; on older hierarchies it locates the Explorer-owned visible `WorkerW`. During Show Desktop, a hidden anchor enters the back of the topmost band and organizers are repeatedly placed between it and the desktop-icons host; on exit the anchor returns to `HWND_BOTTOM`. Runtime screenshots confirmed all three organizers remained visible after 4.7 seconds of taskbar-corner Show Desktop, while a subsequently opened full-screen Notepad window covered them completely. Normal organizer styles retain `WS_EX_NOACTIVATE`.
- Flicker-free transition: a separate `EVENT_OBJECT_REORDER` hook reacts to Explorer's desktop-container reorder at dispatcher `Send` priority, while a bounded five-attempt 2 ms foreground retry covers the shell's short transaction race. A native high-frequency Z-order probe observed no organizer-behind-desktop sample during the first 120 ms after the fixed transition; the previous timer-only build exposed a reproducible 15.8 ms hidden interval. The maintenance timer slows to 250 ms normally and runs at 100 ms only while Show Desktop is active.
- Keyboard reachability: packaged `Ctrl+Alt+D` testing temporarily removed `WS_EX_NOACTIVATE` only from the most recently used organizer, made it the foreground window, and placed UI Automation focus on its first shortcut button. `Escape` restored Explorer as foreground and returned all organizers to their normal non-activating styles.
- Recoverable windows: the packaged ownerless Settings window and rename dialog both exposed `WS_EX_APPWINDOW` (`0x40000`) while open, with measured sizes `390 × 610` and `390 × 188`; each therefore remains reachable from the taskbar after switching applications. Settings uses a scrollable body with a fixed footer and clamps its height to the active work area.
- Hidden-block recovery: the packaged app listed a runtime-hidden organizer in Settings, restored it to its exact `325,910 / 1218 x 220` bounds, removed the row immediately, kept Settings in the foreground, left `state.json` byte-for-byte unchanged, and remained restored after Settings was cancelled.
- Compact-row inspection: the packaged app rendered four labeled shortcuts in one row at exactly `444 x 120`; labels kept the intended breathing gap, icons remained clear, and hover exposed only the two diagonal resize marks over the transparent hit target.
- Fixed-layout inspection: the current organizer previewed Large at `86 × 98`, Medium at `70 × 84`, Small at `52 × 64`, and List at a one-column `40` DIP row height. Width changes altered only the number of columns. Settings preview left `state.json` byte-for-byte unchanged, List always exposed names, and Cancel restored Medium geometry and the original state hash.
- Fixed grid alignment: Large begins at its `14` DIP left padding and Medium/Small/List at `12` DIP; unused horizontal space remains on the right instead of recentering the icon group.
- Overflow scrolling: fixed-layout panels report their complete content height to the hidden-chrome viewport (`296` DIP for the tested Medium grid and `570` DIP for List), keeping icons clipped inside the organizer while enabling vertical wheel/touchpad scrolling.
- Packaged wheel probe: a Medium-layout preview in a `269 × 120` organizer exposed a `59.4%` viewport over its overflowing content. One wheel notch animated the first row upward by `66` DIP to an `80.5%` vertical offset; the organizer bounds stayed fixed, the hidden scroll chrome remained absent, and cancelling the preview left `state.json` byte-for-byte unchanged.
- Multi-window architecture: one application state, one 350 ms save timer, one 96-entry LRU shell-icon cache, one foreground hook, one native Win32 tray icon, and at most one ownerless settings window serve all organizer windows. Global appearance previews are coalesced at render priority and broadcast as one snapshot to every existing or newly created block; folder/icon-name previews target only the organizer represented by the settings window's current-block section. The tray can create or activate the settings window without requiring any organizer window to be visible.
- Magnetic behavior: moving a block retains the release-time `18` DIP edge/alignment and 10 px gap position snap without changing width or height. Bottom-right resizing remains fully raw while dragging; on release, the closest spatially aligned organizer above, left, or right independently provides width and/or height matching when each is within `10` DIP, including a small `10` DIP edge overshoot. Each snapped axis is validated independently against the active work area, and a new move or resize cancels any unfinished 115 ms release animation. Dimensions outside the threshold remain exactly as released; no live detent or visual feedback is added.
- Existing schema-v1 user state migrated in place to schema v2 on real startup with its shortcut content retained; appearance and magnetic-snap preferences persist globally.
- Same-machine 31-second cold-start comparison, before UI Automation attached: the previous three-block/14-icon build reached 114.8 MB private memory, 189.5 MB working set, 1114 handles, 143 modules, and 6609 ms total CPU. The final optimized package, despite loading four blocks/15 icons, reached 85.7 MB private memory, 145.1 MB working set, 1044 handles, 126 modules, and 2047 ms total CPU. Windows Forms and System.Drawing were absent from the optimized module list. The sample is repeatable startup evidence, not a long-duration leak test; attaching UI Automation intentionally loads additional accessibility modules and is excluded from the comparison.

## Visual constraints

- No external title, toolbar, frame, popup panel, or external resize arrow.
- Icons are direct 128 px Windows Shell images with no colored tile, border, halo, or shadow.
- Icon hover/press motion is neutral, short, and limited to a `1.025×` lift and `0.965×` press; the smoke surface gains only a slight neutral tonal response.
- Shortcut mouse focus leaves no persistent frame, tile, rounded rectangle, or double outline. Keyboard-originated focus uses only a short adaptive neutral underline through WPF's keyboard-cue-only `FocusVisualStyle`.
- Container is a single neutral smoke folder surface with a smooth DWM anti-aliased corner, no white/translucent outline, and a 120 DIP minimum height. Its internal resize affordance is only two quiet diagonal marks over a transparent 22 DIP hit target, with no surrounding plate or focus outline. Dark glass uses the lightweight Windows Acrylic backdrop; light glass uses compositor BlurBehind plus one thin white WPF wash so wallpaper blur remains visible instead of becoming a solid white luminosity layer. Unsupported systems retain the neutral fallback.
- Organizer minimum width preserves one complete fixed-layout cell: `114` DIP for Large, `94` DIP for Medium, and `76` DIP for Small/List. Persisted widths normalize against the committed layout, and saving a larger layout expands a narrower organizer to its new minimum. The 120 DIP minimum height remains enforced.
- The empty folder surface is blank, with no onboarding icon or instructional copy.
- Optional folder names render as a quiet, single-line label inside the block and consume no grid space while hidden. Their per-block toggle lives in the settings window's current-organizer section rather than the context menu.
- Optional shortcut names render below each icon with a small 4 DIP breathing gap as a quiet 11 DIP single-line ellipsized label, with no tile, shadow, or outline. Their toggle is also scoped to the current organizer in settings; dense or title-constrained compact layouts temporarily suppress labels without clearing the saved per-block preference.
- The current-organizer settings include a persisted icons-only option. On Windows 11 24H2+ it enables redirected-bitmap alpha while keeping DWM composition active, so transparent WPF pixels stay transparent instead of falling back to white. Its preview hides only the targeted block's native backdrop, WPF surface, DWM border/rectangular shadow/rounded clip, hover edge response, folder name, shortcut labels, and resize marks while preserving the underlying name preferences and transparent interaction hit areas; Cancel restores the complete prior presentation and DWM-owned anti-aliased rounding.
- Each organizer independently persists exactly one of four icon layouts: Large, Medium, Small, or List. Grid modes use fixed icon/item geometry and resizing only reflows columns and rows. List mode is always one column with a fixed row height and visible names; leaving List restores the grid mode's previously saved icon-name preference.
- Rename, move/copy choice, remove/delete confirmation, and warnings use one independent ownerless smoke-gray dialog window positioned within the source monitor work area; organizer XAML contains no embedded dialog overlay and production code contains no `MessageBox` call.
- Global-dialog inspection: a rename prompt opened as its own `390 × 188` top-level window from a `260 × 120` organizer, remained fully inside the source monitor instead of being clipped to the block, accepted keyboard focus in its text field, and closed through the custom Cancel action without changing the persisted state hash.
- Appearance and magnetic snapping use a separate solid smoke-gray settings window that is not owned by or embedded in any organizer block. Transparency spans 0–100% and supports a slider, direct keyboard input, −/+ steps, arrow keys, and focused mouse-wheel adjustment; lightweight glass is a fixed on/off effect, and black/white tone uses a custom two-option selector. The same window includes a clearly separated current-organizer section for the icons-only and two per-block name toggles and a hidden-organizer section with one restore action per hidden block.
- Runtime visual inspection must confirm smooth DWM corners without GDI pixel clipping, no outer outline, direct unframed icons, one detached neutral settings window, editable percentage transparency, immediate synchronized black/white preview on both blocks, adaptive label/control contrast, current-block-only name previews, and cancel/Escape/close rollback of both global and current-block drafts. Hidden-block inspection must confirm that rows update and disappear individually during the current session, restoration preserves the exact position/size/content and remains restored after settings Save/Cancel, hidden state does not survive a packaged restart, and all-hidden recovery works through both tray-opened settings and tray-icon double-click.
- A clean packaged restart was visually inspected against the wallpaper in both tones: dark mode retained the neutral smoke treatment, and at 55% background transparency white mode showed clearly softened, non-uniform blue wallpaper through a light neutral wash rather than a flat white board. Shortcut icons remained sharp and fully opaque. The current-organizer name toggles previewed only on the targeted block, and Cancel restored the unchanged committed JSON state.
- At 92% or greater background transparency, each loaded organizer samples six quiet edge points from its current desktop area and selects a neutral light/dark foreground from average luminance. This affects only labels and controls; icons remain unchanged and no halo, tile, or shadow is introduced.
- Long-running shortcut churn cannot grow the LRU Shell bitmap cache beyond 96 successfully extracted icons; removing a shortcut or organizer prunes obsolete entries immediately, and failed extractions remain retryable. Registry/config permission and I/O failures now degrade to safe in-session state or the existing custom save feedback instead of escaping as startup/save exceptions.
