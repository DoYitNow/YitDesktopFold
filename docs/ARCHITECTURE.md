# 架构与安全边界

## 目标

YitDesktopFold 是 Explorer 桌面的分类视图，不是新的文件存储层。应用的首要约束是：整理操作不得改变用户桌面项目的真实目录结构。

## 数据流

1. `DesktopCatalogService` 只观察用户桌面和公共桌面根目录，并为普通文件、文件夹、快捷方式和支持的 Shell 虚拟项目建立目录快照。
2. Schema 5 的 `OrganizerState` 保存稳定身份、所属整理块、顺序、窗口几何、显示器布局档案和外观设置，不保存文件副本。
3. 用户明确归类后，`DesktopNativeVisibilityService` 先写入应用的所有权与原始可见性记录，再隐藏 Explorer 中的对应项目。
4. 用户移回桌面时，应用先恢复原始可见性，再提交取消归类状态。
5. 外部重命名、删除或创建由根目录监听器合并后同步；状态文件使用临时文件和原子替换，并保留备份。

## Windows 桌面层

整理块是不激活的桌面级窗口，普通交互不抢占前台窗口。`DesktopZOrderHost` 分别识别 Windows 11 24H2 的 `Progman`/`SHELLDLL_DefView` 和旧版 `WorkerW` 层级，并通过 WinEvent 立即响应 `Win+D` 引起的桌面重排。低频定时器只用于异常恢复，不承担正常动画或实时轮询。

应用不跨 Explorer 进程重设 WPF 父窗口，避免 DPI 上下文被 `SetParent` 改写。

每个整理块按显示器设备身份保存独立布局，并以显示器工作区比例记录位置和尺寸。分辨率、DPI 缩放或任务栏工作区变化时按比例恢复；首选显示器暂时断开时只做安全回退，不覆盖其布局档案，显示器恢复后自动回到原排布。

`DisplayPlacementService` 使用显示器设备身份区分布局档案。用户主动移动或缩放整理块时才提交当前显示器档案；系统引起的临时回退不会把首选显示器坐标覆盖掉。

## Shell 集成

- 文件系统项目接受 `FileDrop`；回收站等虚拟项目接受 `CFSTR_SHELLIDLIST`/CIDA。
- 拖放只在释放到整理块、其他整理块或 Explorer 桌面时提交分类变化；其他应用或取消操作不会改变状态。
- 紧凑右键菜单提供高频操作，“显示更多选项”调用 Shell `IContextMenu`，不重建第三方扩展逻辑。
- 整理块保持 `WS_EX_NOACTIVATE`。右键菜单复用桌面框选服务已有的低级鼠标观察，在菜单外发生鼠标按下时立即关闭，不额外安装第二套全局鼠标钩子。
- 回收站清空后只失效该图标缓存并刷新。虚拟桌面图标的注册表状态变化后先发送非阻塞 `SHCNE_UPDATEDIR`，再向当前 `Progman` 或 `WorkerW` 下实际承载桌面的 `SHELLDLL_DefView` 投递非阻塞刷新命令，以兼容不会立即响应 Shell 通知的 Windows 11 桌面宿主；整个过程不清空全局图标、文件关联或缩略图缓存。

## 设置事务

设置窗口维护独立草稿。透明度、玻璃、底色和当前整理块外观可以预览，但取消、关闭或 `Escape` 会回滚。开机启动不做即时预览：保存时写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，校验登记路径指向当前程序，并在状态文件提交失败时回滚原值。

隐藏状态只属于当前运行会话。设置窗口可以立即显示或删除单个隐藏整理块；删除操作独立于外观草稿，必须确认，并在移除分类元数据前恢复该块项目的原生桌面可见性。最后一个整理块不能删除。

## 资源约束

- 单进程、单托盘、单全局状态和一个共享保存计时器。
- 图标缓存为 96 项 LRU；项目或整理块删除时清理失效条目。
- 每个项目只实例化当前大/中/小/列表模板。
- 托盘与工作区计算直接使用 Win32，不加载 Windows Forms/System.Drawing UI 栈。
- 目录监听仅覆盖桌面根层，不递归扫描用户文件树。

## 故障恢复

- 未处理异常和正常退出都会尽力恢复应用拥有的原生可见性改动。
- 配置损坏时保留损坏文件并尝试备份；旧版曾移动到管理目录的内容只做一次事务性迁回。
- 应用不会清除用户原本设置的隐藏属性或虚拟图标注册表值。
- 当前安装器为每用户安装，卸载时移除本应用的启动项，但保留用户配置。

## 明确不做

- 不自动接管或重新排列所有原生桌面项目。
- 不搬运、复制或创建“管理文件夹”的替代快捷方式。
- 不提供云同步、账号、遥测、内容推荐、壁纸、便签或常驻搜索索引。
- 不为了透明效果引入持续截图、重模糊或高频渲染循环。
